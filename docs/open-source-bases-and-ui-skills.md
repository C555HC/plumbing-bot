# Open-Source основы, CRM-базы и UI/UX инструменты для Plumbing Bot

Документ фиксирует результаты исследования открытых репозиториев, библиотек интерфейса и дизайн-систем, которые можно использовать как готовый фундамент или источник архитектурных решений для сантехнического сервиса.

---

## 1. Готовые Open-Source бэкенды и CRM-базы

Вместо написания бэкенда с нуля целесообразно опираться на проверенные легковесные архитектуры.

### 1.1. PocketBase (Фаворит для архитектуры на одном сервере)
* **Репозиторий:** [pocketbase/pocketbase](https://github.com/pocketbase/pocketbase)
* **Технологии:** Go + embedded SQLite (один исполняемый файл).
* **Почему идеально подходит для нашего проекта:**
  - **Всё в одном:** база данных SQLite, встроенная веб-админка, аутентификация, загрузка и ресайз фото (фото поломок от клиентов), REST API и Realtime WebSockets.
  - **Минимальное потребление ресурсов:** запускается на самом дешевом VPS (от 200–300 ₽/мес, 512 МБ–1 ГБ RAM держит тысячи запросов).
  - **Мультиарендность (Multi-tenancy):** легко организуется через поле `master_id` в коллекциях или запуск изолированных легковесных инстансов.
  - **SDK:** Официальный TypeScript/JS SDK (`pocketbase`), работающий и в Node.js (Telegram-бот), и в браузере (Telegram Mini App).

### 1.2. Twenty CRM (Ориентир современной архитектуры)
* **Репозиторий:** [twentyhq/twenty](https://github.com/twentyhq/twenty)
* **Технологии:** TypeScript, NestJS, React, GraphQL/REST, PostgreSQL.
* **Что взять за основу:**
  - Модель данных CRM: связка сущностей `People` (клиенты), `Companies` (объекты/ЖК), `Opportunities / Orders` (заявки) и `Tasks` (напоминания).
  - Паттерн кастомных полей (Custom Fields), позволяющий добавлять специфические параметры сантехники (модель бойлера, дата поверки счетчика) без изменения структуры таблиц.

### 1.3. Cal.com (Ориентир для календаря и слотов)
* **Репозиторий:** [calcom/cal.com](https://github.com/calcom/cal.com)
* **Технологии:** Next.js, Prisma, PostgreSQL.
* **Что взять за основу:**
  - Логику бронирования временных слотов с учетом буфера на дорогу между выездами мастера (например, слот 2 часа + 45 минут на переезд).
  - Механику отправки триггерных напоминаний накануне встречи.

### 1.4. NocoDB / Baserow (Альтернатива для быстрой работы с таблицами)
* **Репозитории:** [nocodb/nocodb](https://github.com/nocodb/nocodb), [bram2w/baserow](https://github.com/bram2w/baserow)
* **Применение:** Open-source аналоги Airtable. Удобны, если мастеру нужен табличный вид всей клиентской базы без программирования сложных кастомных таблиц.

## 2. Библиотеки интерфейса для Telegram Mini App (TMA)

Интерфейс мастера и клиента должен открываться прямо внутри Telegram и выглядеть нативно на iOS и Android.

### 2.1. Официальный стек Telegram Apps
* **@telegram-apps/telegram-ui:** [Telegram-Apps/telegram-ui](https://github.com/Telegram-Apps/telegram-ui)
  - Набор UI-компонентов, повторяющих дизайн Telegram нативного клиента (Cell, Section, List, Button, Tabbar, Modal, Spinner).
  - Автоматическая адаптация под тему Telegram (светлая/тёмная, акцентные цвета пользователя).
* **@telegram-apps/sdk-react:** [Telegram-Apps/telegram-apps](https://github.com/Telegram-Apps/telegram-apps)
  - Официальные хуки React: `useMainButton`, `useBackButton`, `useHapticFeedback`, `useViewport`.
  - Тактильный отклик (Haptic Feedback) при подтверждении заявки мастером создает ощущение дорогого нативного мобильного приложения.

### 2.2. shadcn/ui + Tailwind CSS (Для гибких экранов и карточек)
* **Сайт:** [ui.shadcn.com](https://ui.shadcn.com/)
* **Применение:**
  - Карточки заявок (`Card`) с бейджами статусов (`Badge`: *Новая*, *В работе*, *Требует согласования*, *Выполнено*).
  - Диалоговые окна и выдвижные шторки снизу (`Sheet` / `Drawer`) для быстрого добавления оборудования.
  - Календарь выбора дат (`Calendar` + `Popover`).

### 2.3. TanStack Table v8 (Для списков клиентов и заявок)
* **Репозиторий:** [TanStack/table](https://github.com/TanStack/table)
* **Применение:**
  - Headless-архитектура, позволяющая делать сверхбыстрые адаптивные списки клиентов с поиском по адресу, фильтрацией по дате следующего ТО и сортировкой по сумме чека.

### 2.4. Lucide React (Иконки)
* **Репозиторий:** [lucide-icons/lucide](https://github.com/lucide-icons/lucide)
* **Набор иконок для сантехники:** `Wrench` (гаечный ключ), `Droplets` (вода/протечка), `Flame` (бойлер/отопление), `ShieldAlert` (защита от протечек), `CalendarClock` (напоминания), `Camera` (фото поломки), `MapPin` (адрес).

## 3. UI/UX скиллы и паттерны взаимодействия

### 3.1. Паттерны из ui-ux-pro-max
* **Thumb-Driven Mobile UX:** Все ключевые действия (кнопка «Принять заказ», «Назвать цену», «Позвонить клиенту») должны находиться в нижней трети экрана смартфона под большим пальцем руки.
* **Progressive Disclosure (Поэтапное раскрытие):**
  - Шаг 1: Фото поломки + выбор категории (Бойлер / Фильтр / Смеситель / Авария).
  - Шаг 2: Адрес и удобное время.
  - Шаг 3: Подтверждение.
  - Никаких длинных простыней с 15 полями на одном экране.
* **Instant Feedback & Optimistic UI:** При смене статуса заявки интерфейс обновляется мгновенно без блокирующего спиннера, запрос уходит в фоне.

## 4. Стек для AI-обработки и классификации заявок

### 4.1. Vision AI для оценки фото поломок
* **Модели:** GPT-4o-mini / YandexGPT Vision / Claude 3.5 Haiku.
* **Сценарий:** Клиент загружает фото под раковиной. Модель определяет:
  - Тип оборудования (например, *«Фильтр обратного осмоса Гейзер Престиж»* или *«Редуктор давления мембранный 1/2 дюйма»*).
  - Наличие явных дефектов (капли воды, солевые наросты, ржавчина).
  - Формирует краткую выжимку для мастера: *«Оборудование: Осмос. Проблема: течь колбы предварительной очистки №2»*.

### 4.2. Structured Outputs (Zod + Function Calling)
* Превращение голосовых заметок мастера за рулем в строгий JSON:
  ```typescript
  import { z } from "zod";

  export const VoiceOrderSchema = z.object({
    clientName: z.string().optional(),
    phone: z.string().optional(),
    address: z.string(),
    serviceType: z.enum(["boiler_maintenance", "filter_change", "leak_repair", "faucet_install", "general"]),
    scheduledDate: z.string().optional(),
    price: z.number().optional(),
    nextMaintenanceMonths: z.number().optional()
  });
  ```

## 5. Интеграция с Avito API (Архитектурная схема)

* **Протокол:** Avito Messenger API v3 + Webhooks.
* **Библиотеки/Тулзы:** Легковесный Node.js сервер с эндпоинтом `POST /api/webhooks/avito`.
* **Схема работы:**
  1. Авторизация по OAuth 2.0 Client Credentials (`client_id`, `client_secret` мастера).
  2. Подписка на вебхук входящих сообщений в чатах объявлений.
  3. При входящем сообщении:
     - Создание лида в базе.
     - Отправка пуша мастеру в Telegram с кнопками быстрого ответа.
     - Опциональный автоответчик: отправка приветствия и просьбы прикрепить фото прямо в чат Авито.
