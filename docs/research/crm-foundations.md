# Готовые CRM и системы выездного сервиса

Проверено: 8 октября 2026 года. Первичный отбор по README, лицензиям и официальной документации. Приложения не запускались.

## Сравнение

| Проект | Тип | Лицензия проверенной основы | Что интересно нашему проекту | Предварительная роль |
| --- | --- | --- | --- | --- |
| Atomic CRM | CRM на React и Supabase | MIT | Контакты, заметки, задачи, история, настраиваемые компоненты | Первый кандидат на проверку адаптации |
| EspoCRM | Универсальная CRM с PHP API | AGPLv3 | Клиенты, обращения, календарь, настройка сущностей | Кандидат для подхода с готовой CRM |
| Dolibarr | ERP/CRM с модулем Interventions | GPLv3 | Учёт выездных работ вместе с клиентами и услугами | Предметный пример; основа при более широком учёте |
| Beveren FSM | Field Service Management для ERPNext | AGPLv3 | Назначение техников, сервисные работы, запчасти | Близкий предметный пример; требует ERPNext |

| ERPNext | Большая ERP-платформа | GPLv3 | Клиенты, оборудование, сервис и финансовый учёт в общей системе | Основа для FSM; избыточна для текущей маленькой CRM |

«Предварительная роль» — наша оценка применимости, а не утверждение автора проекта.

## 1. Atomic CRM

[Репозиторий](https://github.com/marmelab/atomic-crm).

README описывает контакты, задачи и напоминания, заметки, историю активности, импорт/экспорт, API и замену компонентов. Текущая основа указана как React, shadcn-admin-kit и Supabase. Корневая лицензия — MIT.

**Что можно изучить или переиспользовать:** клиентские списки и карточки, историю и заметки, организацию форм и доступа. Это позволяет проверить адаптацию небольшой CRM вместо создания всего интерфейса с нуля.

**Что ещё нужно проверить:** карточки адресов и сантехнического оборудования, запись на выезд, Telegram и Avito, голосовые команды и повторные услуги. Наличие задач с напоминаниями не подтверждает готовность персональной рассылки клиентам. Также не проверено разделение данных независимых мастеров в одном сервисе и условия размещения Supabase-компонентов.

**Вывод:** первый кандидат для отдельной технической проверки; окончательно за основу не выбран.

Первоисточники: [README](https://github.com/marmelab/atomic-crm/blob/8b5d47ba32190c68801a427ef7682d7a6afc14e0/README.md), [MIT](https://github.com/marmelab/atomic-crm/blob/8b5d47ba32190c68801a427ef7682d7a6afc14e0/LICENSE.md).

## 2. EspoCRM

[Репозиторий](https://github.com/espocrm/espocrm).

CRM для контактов, потенциальных клиентов, сделок и обращений. README описывает веб-интерфейс и PHP REST API; официальная документация содержит календарь, роли и настройку сущностей.

**Польза:** можно изучить клиентские карточки и обращения, рассмотреть отдельный интерфейс бота поверх готовой CRM.

**Ограничения:** ядро AGPLv3. Конструктор Workflows находится в расширении Advanced Pack, поэтому автоматизацию нельзя автоматически считать частью бесплатного ядра. Условия и стоимость расширений нужно проверить под конкретную функцию.

**Вывод:** полезный вариант, если готовые CRM-функции важнее компактности собственного приложения; Telegram-путь и сантехнические сценарии не подтверждены как готовые.

Первоисточники: [README](https://github.com/espocrm/espocrm/blob/2b1daf37423f389114ddc971504d93efbee83867/README.md), [лицензия](https://github.com/espocrm/espocrm/blob/2b1daf37423f389114ddc971504d93efbee83867/LICENSE.txt), [Workflows](https://docs.espocrm.com/administration/workflows/).

## 3. Dolibarr и Interventions

[Репозиторий](https://github.com/Dolibarr/dolibarr).

ERP/CRM на PHP с контактами, услугами, документами и повесткой. Модуль Interventions входит в стандартную поставку; официальная wiki описывает карточки сервисных работ с описанием, датой и длительностью. Лицензия основы — GPLv3.

**Польза:** ближе к выездной работе сантехника, чем обычная воронка продаж. Интересно устройство карточек работ и связь с клиентами.

**Ограничения:** большой продукт; конкретное удобство на телефоне и назначение мастеров требуют проверки. Дополнительные модули из магазина могут иметь отдельные условия. Встроенный Interventions и сторонние расширения Field Interventions — разные продукты.

**Вывод:** изучить предметную модель; брать целиком имеет смысл при потребности в более широком учёте.

Первоисточники: [README](https://github.com/Dolibarr/dolibarr/blob/9471cd6776dce876e72d58fe2bed97f4a5165c3a/README.md), [GPLv3](https://github.com/Dolibarr/dolibarr/blob/9471cd6776dce876e72d58fe2bed97f4a5165c3a/COPYING), [встроенный Interventions](https://wiki.dolibarr.org/index.php?title=Module_Interventions_En), [описание сущности](https://wiki.dolibarr.org/index.php/Module_Interventions_%28developer%29).

## 4. Beveren FSM

[Репозиторий](https://github.com/Beveren-Software-Inc/Field_Service_Management).

README описывает сервисные обращения, работы, расписание и назначение техников, учёт запчастей и выставление счетов. Это приложение для ERPNext; заявлен интерфейс React/TypeScript. В корне — AGPLv3.

**Польза:** самый близкий из найденных примеров по предметной области выездного сервиса. Можно изучить экраны заявки, заказа и расписания, различие обращения и фактического выезда.

**Ограничения:** зависит от Frappe/ERPNext. README использует дополнительные названия `beveren_fsm` и `beveren_fsm_spa`; адрес `beveren_fsm` при API-проверке переадресуется на основной репозиторий. Полнота поставки, совместимость и запуск ещё не проверены.

**Вывод:** хороший предметный ориентир; не считать готовой маленькой CRM без проверки зависимостей и работы приложения.

Первоисточники: [README](https://github.com/Beveren-Software-Inc/Field_Service_Management/blob/df0ae701a0f389e3d81c5ec6d77b1041486cda86/README.md), [проверенный снимок репозитория](https://github.com/Beveren-Software-Inc/Field_Service_Management/tree/df0ae701a0f389e3d81c5ec6d77b1041486cda86).

## 5. Frappe CRM

[Репозиторий](https://github.com/frappe/crm).

README описывает карточки лидов и сделок с действиями, заметками и задачами, канбан и настраиваемые списки. Основа — Frappe Framework и Frappe UI на Vue; лицензия AGPLv3.

**Польза:** компактные карточки и пользовательские представления можно изучить для работы с обращениями.

**Ограничения:** продукт ориентирован на продажи, а не на сантехнические выезды. Размещение требует Frappe. Проверенный README отдельно помечает `main` как стабильную ветку v1.x, а `develop` как нестабильную будущую v2.x; снимок исследования сделан с ветки по умолчанию `develop`.

**Вывод:** альтернативная CRM-основа; для будущего запуска выбирать стабильную поставку после проверки.

Первоисточники: [README и совместимость](https://github.com/frappe/crm/blob/98368bea3c78efd320ff28758aaece8c8bdcddd9/README.md), [проверенный снимок](https://github.com/frappe/crm/tree/98368bea3c78efd320ff28758aaece8c8bdcddd9).

## 6. ERPNext

[Репозиторий](https://github.com/frappe/erpnext).

Большая ERP на Frappe, лицензия GPLv3. Здесь важна прежде всего как основа для Beveren FSM.

**Польза:** предметные примеры учёта клиентов, оборудования, обслуживания и связанных документов.

**Ограничения:** масштаб системы заметно шире небольшой CRM мастера. Поддержка ERP-основы не становится бесплатной только потому, что исходники открыты.

**Вывод:** изучать вместе с FSM, если появятся требования к бригаде, запчастям и финансовому учёту. Для текущего простого продукта целиком не рекомендована без отдельного обоснования.

Первоисточники: [README](https://github.com/frappe/erpnext/blob/2985466b755c31a22724546bfdc04aea1dee7178/README.md), [проверенный снимок](https://github.com/frappe/erpnext/tree/2985466b755c31a22724546bfdc04aea1dee7178).

## 7. Twenty

[Репозиторий](https://github.com/twentyhq/twenty).

Расширяемая CRM с объектами, представлениями и приложениями. Интересна как пример современного интерфейса и как платформа при более широких требованиях.

**Лицензия:** в проверенном LICENSE ядро описано как AGPLv3 с дополнительным разрешением Twenty Application Exception. Отдельные пакеты, включая `twenty-ui` и SDK, — MIT; файлы с отметкой Enterprise — под коммерческой лицензией. GitHub API возвращает `NOASSERTION`, что не означает отсутствие лицензии.

**Польза:** изучить списки, карточки, настраиваемые объекты и варианты расширения приложения через предоставленные интерфейсы.

**Ограничения:** это большая CRM-платформа. Условия зависят от того, что именно переиспользуем: изменённое ядро, отдельный пакет или приложение через интерфейсы. Не считать весь монорепозиторий MIT.

**Вывод:** полезный пример и альтернативная основа; не первый кандидат для маленького приложения сантехника.

Первоисточники: [README](https://github.com/twentyhq/twenty/blob/5bcb2d694b4adfd756e0acc28d40d6ad9b0491e4/README.md), [смешанная лицензия](https://github.com/twentyhq/twenty/blob/5bcb2d694b4adfd756e0acc28d40d6ad9b0491e4/LICENSE).

## Что означает «взять за основу»

Есть три разных варианта: адаптировать целое приложение, использовать готовую CRM как отдельную систему через API или взять разрешённые компоненты и написать узкий интерфейс. Ни один вариант пока не выбран.

MIT и Apache-2.0 позволяют широкий круг переиспользования при соблюдении условий. GPL/AGPL требуют отдельной оценки условий выбранного способа использования; коммерческая работа сама по себе ими не запрещена. В AGPL существенны условия предоставления исходников модифицированной версии пользователям при сетевом взаимодействии. Конкретное решение проверяется по лицензиям выбранных файлов и зависимостей, а не только по значку GitHub.

Главная незакрытая часть во всех кандидатах — наш специфический путь: сообщение или голос → сохранённое обращение → согласованный выезд → история оборудования → следующее обслуживание. Готовность всего этого набора вместе с Avito и Telegram Mini App в исследовании не подтверждена.
